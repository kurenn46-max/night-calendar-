# NIGHT CALENDAR 最終リリース判定表

**現在の判定：正式公開不可（実機・本番署名が未確認）**

開発済みの機能とテスト合格を、実際の配布完了と取り違えないための記録です。

## 開発側で確認済み

- 六曜（対応範囲：2025〜2027年）、日本の休日（2026〜2027年）、Android端末の予定の閲覧、ライト／ダーク表示、端末内の件数診断を実装済み。
- Android 15 / API 35：デバッグ版の画面試験4/4、テスト鍵で署名したリリースAPKのインストール・起動・再起動を確認。
- Android 16 / API 36：テスト鍵で署名したリリースAPKのインストール・診断画面・再起動を確認（[CI #10](https://github.com/kurenn46-max/night-calendar-/actions/runs/46022243009)）。
- 署名テストでは不正な証明書の指紋を拒否。**これらの使い捨て鍵は正式署名鍵ではありません。**
- 配布用署名の手動ジョブは、レビュー済み `main` ブランチでのみ実行可能。公開処理は含まれていません。

## 実機確認（オーナー作業・未実施）

1. Androidの実機にQA用APKをインストールし、画面が正しく出るか確認する。
2. 「端末のカレンダーを読み込む」で権限を許可し、Androidの同期済みカレンダーの予定が表示されるか確認する。**予定名・アカウント・スクリーンショットは送らなくてよい。**
3. 「端末診断（送信なし）」で権限、登録カレンダー数、選択日の予定件数を確認する。
4. 六曜・祝日、月移動、日付選択、ライト／ダーク、予定追加・表示・編集への遷移を確認する。
5. Android 16実機の起動・再起動、権限拒否時の動作も確認する。
6. 本番署名APKでは、デバッグ版と署名が異なるため、既存QA版を上書きできない場合がある。必要ならQA版をアンインストールする。端末の同期済み予定はこのアプリ本体の保存データではない。

確認記録には「機種／Android版」「インストール成功」「同期予定表示成功」「操作問題なし」の4点で十分。
**実在する予定の内容やアカウント情報を公開Issue・チャット・ログへ貼らないこと。**

## 本番署名の条件（オーナー作業・未実施）

1. 長期保存できる専用の署名鍵をオーナー管理下で作成し、安全な場所にバックアップを二つ用意する。
2. GitHubの `release-candidate` 環境を設け、可能なら承認必須にする。実際の環境保護設定はオーナーによる確認が必要。
3. [署名準備手順](RELEASE_CANDIDATE.md) に記載の5つの署名情報をGitHub ActionsのSecretsに登録する。**秘密鍵とパスワードをナイトのチャットに貼らない。**
4. `main` の緑のCIを確認し、Actionsの `NIGHT CALENDAR Signed Candidate` を `main` から手動実行。SHA-256と署名者の証明書指紋、`com.nightcalendar`、バージョンを確認。
5. その**本番署名候補APK**を実機でテストする。テスト用鍵で署名したAPKでの成功を代用しない。

## 一般公開判定（未実施）

本番署名・実機確認・正式版バージョン／更新可能性・オーナーの明示承認がそろった後、正式APKとSHA256SUMSをGitHub Releasesに登録する。現状のCIは**自動で公開しない**。公開先が必要ならリリース作成を別途実施する。

**実機テストが未実施の状態で「正式リリースできた」と報告しない。**
